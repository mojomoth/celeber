## 1. 공통 기반과 통합

### 구조

- pnpm workspace(`pocs/*`), Node 26, Next.js 16.4.6 App Router, TypeScript strict, zod 4, vitest 5.
- `@celeber/core`: 계약 스키마, 색 과학(sRGB↔XYZ↔Lab, CIEDE2000, ITA, McCamy CCT, Bradford/von Kries, gray-world), 얼굴 색 샘플링, 퍼스널컬러 분류기와 12톤 프로필, 서버 전용 SQLite(`node:sqlite`)·업로드(sharp)·AI(Anthropic SDK 구조화 출력)·검색(네이버/SerpAPI/Mock)·SSRF 방어 fetch.
- `@celeber/ui`: DESIGN.md 토큰(CSS 변수 `--cb-*`), 리포트·카메라·선택 컴포넌트, MediaPipe 로더(로컬 wasm·모델).
- 앱 간 재사용: 각 앱이 `./flow`, `./components`, `./lib`, `./server`, `./routes`를 export하고 후행 앱이 import해 같은 API 경로로 재노출한다. 공유 SQLite 하나에 모든 앱이 기록한다.

### 최종 수정 단계에서 바꾼 것 (감사 결과 반영, 2026-11-24)

| 감사 발견 | 수정 |
| --- | --- |

| 측정되지 않은 연예인 색 축이 측정값처럼 갭·행동 제안에 쓰임 | celeb-vibe-report `celebAxes`가 출처를 `measured/estimated/tone/none`으로 구분. `measured=false`이고 신뢰도 < 0.3이거나 `partial.personalColor=false`면 색 5축 갭을 비교 불가로 두고 이유를 적는다(행동 제안·`largestGaps`에서 제외). 헤어·눈 색이 없으면 대비 축(기본값 50)만 비교 불가. AI가 읽은 색은 "(추정)" 표시. 갭 부제도 출처에 따라 바뀐다. |

| 터널로 열면 앱 전체(얼굴 사진·삭제 API·AI 호출)가 무인증 노출 | 7개 앱 모두 `proxy.ts`(Next 16 Proxy) 추가: localhost만 기본 허용, 그 밖의 Host는 `CELEBER_ACCESS_TOKEN`(쿠키·헤더, `?access=`로 1회 설정) 필요. ## 2. camera-face — 내 얼굴과 환경 촬영으로 피부색·윤곽 추출

**구현**

- 단계 촬영: 안내 → 환경 → 정면 → 측면(건너뛰기 가능). CameraShell(어두운 촬영 바탕, 한 줄 지시, 고정 셔터, 프레임 가이드), 모든 단계에 업로드 대체 경로.
- 환경: gray-world + white-patch McCamy CCT, Duv(초록 틴트), 3×3 타일로 혼합광, 역광, 밝기, 실내/실외 점수 → 재촬영 권장. 흰 종이를 누르면 기준 백색(Duv로 검증).
- 실시간 품질(약 10fps): 검출, yaw(변환 행렬), 얼굴 크기, 밝기, 3프레임 안정. 통과 전 셔터 비활성, 8초 후 경고와 함께 허용.
- 피부색: 랜드마크 ROI(이마·양볼·코·턱) + selfie segmentation + YCbCr 필터, 밝기 상하위 10%/5% 트림, 화이트밸런스(흰 종이 1.0 > 환경+얼굴 배경 gray-world 0.6). 보정 전후 hex·Lab·ITA·색상각·채도, 부위별 값, 신뢰도와 사유.
- 윤곽: 얼굴 정렬 비율, 얼굴형 7종 점수, SVG 오버레이. 측면: 중앙선 랜드마크를 실루엣에 스냅, E-라인, 돌출도, 코 돌출.
- 서버가 저장된 원본 픽셀로 다시 계산(sharp) → `face_sessions` 저장, 목록·상세·삭제.

**검증**: vitest 37개(합성 조명 캐스트 복원, 라우트 통합). 실제 사진 E2E(CDP 헤드리스 Chrome)에서 레퍼런스 정면 사진이 #E5C3AE(h 59°), 계란형으로 나왔다.

**한계·리스크**

- 휴대폰 자동 화이트밸런스가 이미 적용된 사진이라 환경 CCT는 "남은 색 틴트"에 가깝다.
- 채도 높은 배경(주황 나무 벽)에서 배경 gray-world 게인이 상한(1/1.8)에 걸려 피부가 #D08B8A → #BE8B92(b* 11.6→4.1)로 과보정됐는데 신뢰도는 0.62로 경고가 나지 않았다. **웜/쿨 판정이 b*에 크게 의존하므로 영향이 크다.**
- 붉은 볼 픽셀이 core `isSkinLike`의 Cr≤180에서 잘려 그늘 픽셀만 남는 부위가 생긴다(부위 간 ΔE 23인데 신뢰도 0.62).
- MediaPipe가 큰 yaw를 작게 읽는다(약 70° 측면을 43°로). 측면 깊이 보정은 쓰지 않고 실루엣 스냅으로 대신했다.
- 얼굴형 원형·E-라인 기준은 정면 사진 2장에 맞춘 추정값.
- `detectionScore`는 실제 검출기 신뢰도가 아니라 합성값(대부분 0.95)이라 리포트 신뢰도에 정보를 거의 주지 않는다.

**본 개발로 가져갈 것**: `@celeber/core/face`(샘플링), `src/lib/environment.ts`·`skin.ts`·`geometry.ts`·`profile.ts`(순수 함수), `FaceCaptureFlow`, `drapeAnchorFromAnalysis`. 정확도 과제는 §8.

## 4. search-celeb — 연예인 검색과 대표·최근·평소 전신 사진

**구현**

- 이름 검색: 자동완성(내부 데이터만) → 원형 사진+이름+설명+근거 후보 → 사용자 확정.
- 사진으로 찾기: SerpAPI Lens 지식 패널·유사 페이지 제목에서 이름 n-gram 빈도로 후보. Claude는 (키가 있으면) 제목 텍스트만 받아 이름 표기를 정리하고, 사진에서는 **글자(캡션·자막·워터마크·@계정)만** 읽는다. 확정 전 "같은 사람인지 확인하지 않았다" 확인 단계.
- 사진 수집: 카테고리별 검색어(대표: 화보·레드카펫·시상식, 최근: 올해/작년 공항패션·행사, 평소: 사복·일상) → 네이버 > SerpAPI > Mock → 메타 필터(세로 1.25 이상, 높이 500 이상) → 서버 캐시(SSRF 방어, 10MB·10초) → (키가 있으면) Claude 전신·분석 가능 판정 → `celeb_images`.
- 3:4 그리드, 탭, 전신만 보기, 다시 검색(선택 유지), 출처 링크, 분석 불가 사유.

**검증**: vitest 35개, SSRF(사설·루프백·메타데이터·file://) 차단, 재수집 시 중복 0. 실제 네이버/SerpAPI/Claude 경로는 미실행.

**한계·리스크**: n-gram 이름 추출은 휴리스틱이라 매체·브랜드명이 섞일 수 있다(항상 사용자 확정). 네이버 이미지 API는 페이지 URL을 주지 않고 일부 호스트는 핫링크를 막는다. Lens는 공개 URL만 받는다. single 선택 모드에서 이전 다중 선택이 남아 2장이 넘어갈 수 있다(남은 이슈).

**본 개발로 가져갈 것**: `src/lib/queries.ts`·`filter.ts`·`candidates.ts`, `src/server/images.ts`(수집·캐시 파이프라인), `CelebSearchFlow`·`CelebGallery`. 정책은 §9.

## 5. celeb-vibe — 연예인 코디·퍼스널컬러·분위기 추출

**구현**: 사진(업로드·카메라·URL·search-celeb 저장 사진) → 브라우저 측정(Face/Pose/Selfie, 검출기별 성공·실패 기록) → 분석 가능 판정(인원·구도·역광·가림·저해상도·흑백/강한 필터) → 규칙 초안(의상 색 영역, 피부·헤어·눈 색 → 12톤) → Claude 비전(아이템·소재·핏·스타일 키워드·분위기·팔레트, 신원 판단 금지) → 병합·`vibe_analyses` 저장. 결과: 핫스팟 사진, 코디, 퍼스널컬러(톤·축·근거·조명 한계), 분위기, 주조/보조/포인트 팔레트.

**검증**: vitest 59개(측정 검증·한도, 검출기 실패 폴백, 강제 분석, 룩 이름 보존, import-url 오류 매핑). 통합 단계에서 분류기를 리포트와 같은 프리셋으로 바꾼 뒤에도 전부 통과.

**한계·리스크**: 브라우저 측정이 없을 때(검출기 실패·강제) 고정 중앙 사각형 통계를 쓰는데, 흰 배경 실사진에서 상의 #171310 블랙/하의 #FCFCFC로 틀리게 나왔다. 흰 배경 화보는 하이라이트 클리핑으로 '극단적 조명'이 걸리기 쉽다. 연예인 사진은 보정이 강해 퍼스널컬러는 참고값이다(가이드에서 "사진 보정 색감은 따라 하지 말 것"으로 안내).

**본 개발로 가져갈 것**: `src/flow/measure.ts`, `src/lib/analyzability.ts`·`rules.ts`·`build.ts`, `VibeAnalyzer`, 결과 뷰.

## 6. personal-color-report — 얼굴+전신(선택) 퍼스널컬러 리포트

**구현**

- 입력: 앱 안에서 camera-face → camera-body 촬영(가져온 플로우), 또는 저장된 세션 선택.
- 분류: 보정 피부 Lab + 헤어/눈 Lab → 5축(웜·명도·채도·대비·청탁) → 12톤 원형 거리 softmax. 1위 = 타입, 2위 = 보조 가능 타입.
- 서술: Claude 구조화 출력(규칙과 독립적인 톤 의견 + 규칙 톤 기준 서술). 없으면 측정값(색상각·b*·ITA·ΔL*)을 넣은 템플릿.
- [레퍼런스 카드](ui/personal-color-report-guide/navy-men-personal-color-report-card.jpeg) 1:1: 헤더(분석일/기반/도구) → 업로드한 사진 → ① 첫인상(체크 4 + 해시태그) → ② 타입(한·영, 보조 타입) → ③ 웜/쿨 %(합 100, 그라데이션+마커, 분석 포인트) → ④ 특징 표 + 5축 차트 → ⑤ 드레이핑 베스트 4/워스트 4(내 사진 턱 아래 canvas 합성, 얼굴 픽셀 불변) → ⑥ 셔츠 6 → ⑦ 수트 5 → ⑧ 넥타이·금속 → ⑨ 헤어 4 + TIP → ⑩ 그루밍 → ⑪ 비추천 4 → 전신 스타일링(없으면 "전신 사진 추가") → 12 오늘 포인트 → 13 주의사항 → 14 신뢰도 게이지 → 면책.
- 성별 변형(남성/여성/선택 안 함): ⑥⑦⑧⑩ 라벨·형태·항목 변경, 기본값은 사진 기반 `presentation`, 화면에서 변경 시 PATCH 저장.
- 신뢰도: 조명 품질, 화이트밸런스(방법·보정량), 피부 측정 품질, 검출, 부위 간 ΔE, 분류 margin, 규칙·AI 일치도, 헤어/눈 유무로 계산. 강한 유색광 + 부위 편차가 크면 49 이하 '재촬영 권장', 환경 단계가 재촬영 권장이거나 조명 품질이 낮으면 55 상한 + ③ 웜/쿨 %와 명확도를 50:50 쪽으로 압축하고 ②에 경고.

**검증**: vitest 27개(AI 성공 경로를 모의한 통합 포함). 390px CDP 렌더에서 카드 순서·가로 넘침 0. 이번 E2E에서 합성 얼굴로 여름쿨 라이트·웜 42%·남성 변형·섹션 17개 생성.

**한계·리스크**: 분류기 원형과 축 보정은 실측 데이터로 튜닝되지 않은 경험값이다. 밝은 피부 + 검은 머리는 1·2위 차이가 작을 수 있다. 조명 경고 시 웜/쿨 압축·점수 상한(55)은 경험값이다. 변형을 원래 값으로 되돌려도 "직접 고른 스타일"로 표시된다. 4단계(전신) 화면은 1~3단계와 다른 밝은 화면·텍스트 단계 표시를 쓰고, 진단 준비 카드에 전신 썸네일이 없다.

**본 개발로 가져갈 것**: core 분류기·12톤 프로필·`computeReportConfidence`, `src/lib/assemble.ts`·`narrative.ts`·`drape.ts`·`palette.ts`, `PersonalColorReportView`·`DrapeCompare`.

## 7. celeb-vibe-report — 리포트 기반 연예인 추구미 가이드

**구현**: 내 리포트 선택 → 연예인(이름 검색 / 사진 업로드 / 이전 분석) → celeb-vibe 분석 가능 판정 → 불가 시 사유와 함께 같은 인물의 대표·최근·평소 갤러리로 유도 → 분석 → 가이드. 규칙: 옷 색 치환(얼굴과의 거리, 워스트 색 회피, 주얼리는 금속 매핑), CIEDE2000 팔레트 매핑, 7축 갭(웜·명도·채도·대비·청탁·스타일·체형 비율), 쉬운 것부터 우선순위 행동, 따라 하지 말 것+대안. Claude는 서술만. 같은 사진·조명에서 의상 영역만 내 색으로 바꾼 canvas 비교. 저장·룩 이름 수정·다시 만들기·삭제·초기화 미리보기.

**검증**: vitest 44개. 이번 E2E에서 3105가 만든 리포트를 `/api/guide/reports`에서 찾아 가이드 생성(갭 7축)까지 확인. 마무리 검증에서 브라우저 측정 사진(남·여 리포트), 측정 없는 API 경로, 강행 분석(인물 없음), 긴 이름 가이드를 Chrome 390px로 다시 확인했다(§1 마무리 검증 반영).

**한계·리스크**: 색 갭은 양쪽 모두 사진 측정이라 조명·보정 영향을 받는다(통합 단계에서 분류 척도는 통일). 브라우저 측정이 없으면 의상 항목이 0개이거나 색이 부정확할 수 있다. 그래서 이 경우 재채색은 만들지 않고 치환표만 보인다. 재채색은 bbox + Lab 거리 마스크라 비슷한 색 배경도 바뀔 수 있다. 체형 갭은 양쪽 전신 측정이 있을 때만 나온다. '포인트 대비만' 판단 기준(차이 25, 권장 대비 60)은 경험값이다. 제한 분석 판단은 celeb-vibe 사유 코드에 의존하므로, celeb-vibe가 사유 체계를 바꾸면 같이 고쳐야 한다. AI 서술(실제 Claude)은 이 규칙을 모른 채 문장을 쓸 수 있어, 키가 생기면 대비 관련 서술이 규칙과 맞는지 다시 확인해야 한다.

**본 개발로 가져갈 것**: `src/lib/gaps.ts`·`palette-map.ts`·`rules.ts`·`recolor.ts`, `VibeGuideFlow`.

## 8. 정확도 개선 과제 (우선순위 순)

1. **화이트밸런스 견고성**(camera-face): 배경 gray-world에서 고채도 픽셀 제외, 게인이 상한에 걸리면 가중치를 낮추고 신뢰도 사유 추가, 보정 후 피부 색상각이 25~80° 밖이면 신뢰도 하향. 흰 종이 기준점을 촬영 흐름의 기본 단계로 올리는 것도 검토.
2. **부위 이상치 제거**: 다른 부위 중앙값과 ΔE 10 이상 차이 나는 부위를 평균에서 제외하고, 부위 간 ΔE가 크면 신뢰도 상한. core `isSkinLike` Cr 상한을 밝기에 따라 완화.
3. **분류기 튜닝 데이터셋**: 전문 진단 결과가 붙은 정면 사진(조명 조건 다양) 수십~수백 장으로 12톤 원형·축 보정·softmax 온도를 맞춘다. 지금은 대표 케이스 테스트만 있다. 웜 % 시그모이드(기울기 9)가 b*에 급하게 반응하는 것도 같이 본다.
4. **검출 신뢰도 실값화**: 합성 `detectionScore` 대신 크기·밝기·흐림·yaw 이슈에서 계산한 품질 점수를 리포트 신뢰도에 쓴다.
5. **헤어 색**: 세그멘테이션 마스크가 없을 때의 휴리스틱(core)이 짙은 갈색 머리를 피부로 오인한다. 밝기 기반 어두운 픽셀 선택으로 바꾼다.
6. **측면 yaw**: MediaPipe가 큰 yaw를 작게 읽는다. 측면 촬영은 실루엣 기반 옆선으로 가고, 정확한 각도가 필요하면 별도 모델을 검토.
7. **전신 비율 계수**: 머리 길이·어깨·골반 계수를 키·실측 치수가 있는 데이터로 보정. 옷 부피 보정.
8. **연예인 사진 측정**: 브라우저 측정이 없을 때의 통계 폴백을 인물 박스 기반으로 바꾸고, 결과를 "참고용"으로 명확히 낮춘다. 하이라이트 클리핑은 인물 영역 안에서만 계산.

## 9. 외부 API 비용·정책

### 인물 식별 정책 (가장 중요)

- **얼굴 특징으로 실존 인물의 신원을 판단하지 않는다.** 얼굴 임베딩·비교 코드가 없고, 모든 Claude 호출의 system 프롬프트 앞에 `IDENTITY_POLICY`(얼굴로 신원 판단 금지)가 자동으로 붙는다. celeb-vibe·celeb-vibe-report는 사용자가 적은 이름을 메타데이터로만 저장하고 프롬프트에 넣지 않는다.
- 연예인 찾기는 **이름 검색이 기본**이다. 사진은 역이미지 검색 결과의 제목·지식 패널과 사진 속 글자(캡션·워터마크·계정)로 **후보만** 제시하고, 사용자가 "같은 사람인지 확인하지 않았다"는 안내를 본 뒤 확정한다.
- 본 개발에서도 유지해야 한다. 얼굴 인식 기반 식별은 생체정보 처리(개인정보보호법상 민감정보) 동의·보관 의무가 생기고, 오인식 시 초상권·명예 문제로 이어질 수 있다. 사용자 본인 사진의 얼굴 랜드마크는 색·형태 측정에만 쓰고, 원본 사진 보관 기간과 삭제(현재 PoC의 초기화 기능)를 정책으로 명시한다.

### 비용

- Claude: 기본 모델 `claude-opus-5-5`(2026-11 기준 입력 $4 / 출력 $20 per 1M tokens, 최신 단가는 공식 가격표 확인). 이미지는 긴 변 1568px로 줄여 보내며 장당 대략 1~1.6천 입력 토큰이다. 한 사용자 흐름(얼굴 2회 + 전신 1회 + 리포트 1회 + 연예인 검색·판정 2~4회 + 추구미 1회 + 가이드 1회)에서 8~10회 호출, effort는 판정·서술 성격에 따라 `low`/`medium`을 쓴다.
  - 본 개발 과제: 응답 `usage`를 기록해 흐름당 실제 비용을 측정, system 프롬프트·스키마를 고정해 프롬프트 캐싱 적용, 전신 판정처럼 대량·저난도 호출은 더 작은 모델이나 Batch로 분리할지 평가로 결정, 결과 캐시(같은 사진 sha256 재사용은 이미 있음).
  - 사용 한도 초과·인증 오류 시 10분 차단 후 Mock 폴백 구조가 있다. 본 개발에서는 사용자에게 "AI 분석 지연" 상태를 보여 주고 재시도 큐를 둔다.
- 네이버 검색 API: 일 호출 한도가 있고 이미지 원본 호스트가 핫링크를 막는 경우가 많다. 결과 이미지를 서버에 캐시하므로 **저작권·초상권**(연예인 사진 저장·재배포) 검토가 필요하다. 본 개발에서는 썸네일·원본 링크만 두고 분석 시점에만 일시 다운로드하는 방식을 검토.
- SerpAPI(Google Images·Lens): 유료 호출 단위 과금, Lens는 공개 URL이 필요해 사용자 업로드 사진을 외부에 노출해야 한다(서명된 단기 URL 필요). 사용자 사진을 제3자 검색 서비스로 보내는 것에 대한 고지·동의가 필요하다.

## 11. 남은 이슈

최종 수정 단계 이후에도 남은 것:

- 공통: 실제 Claude·네이버·SerpAPI 응답 미검증(Claude 키는 2026-12-01까지 사용 한도 초과). 키가 생기면 `CELEBER_FORCE_MOCK` 없이 `pnpm smoke`와 각 앱 AI 경로를 한 번씩 돌려 스키마 일치와 서술 품질을 확인해야 한다. AI 헤어스타일 서술(길이·앞머리·가르마)도 그때 검증한다. 키가 없으면 헤어스타일은 "측정하지 못함"으로 표시된다.
- 사진으로 연예인 찾기: `SERPAPI_API_KEY` + 외부 HTTPS 터널(`CELEBER_PUBLIC_BASE_URL`) + `CELEBER_ACCESS_TOKEN`이 모두 있어야 Lens 경로가 동작한다. 현재 .env로는 검증할 수 없다. 이미지 URL을 붙여 넣어 Lens를 바로 검증하는 입력은 만들지 않았다.
- 데모 사진(`pocs/core/fixtures/demo-people`)은 리포지토리의 참고 시안 화면에서 잘라 낸 모델 사진이다. PoC 데모 전용이며 배포물에 넣지 않는다. 검색한 이름과 무관한 사진이라는 표시가 갤러리 사유와 안내 문구에 있다.
- 접근 제어는 PoC 수준이다: 공유 토큰 하나(쿠키 12시간), 사용자 구분 없음. 본 개발에서는 실제 인증·사용자별 데이터 분리가 필요하다. JSON 본문의 Content-Type 검사(415)는 기존 호출부·테스트가 헤더 없이 보내는 곳이 많아 넣지 않고 proxy의 Origin/Sec-Fetch-Site 검사로 대신했다.
- 묶음 결과 화면(CONTEXT 화면 3 "나를 분석 결과": 정면·측면·전신·피부톤·이목구비·헤어·비율을 한 리포트로)은 없다. 얼굴 결과 → 리포트·추구미 찾기 링크만 추가했다. 본 개발 과제로 personal-color-report 쪽 요약 페이지를 권장.
- camera-face: MediaPipe 로드 실패 시 업로드 경로도 막히는데 업로드를 안내함, 카메라 권한 거부 시 "준비 중" 표시 지속, 완료된 세션 id로 재분석하면 덮어씀.
- camera-body: 건너뛴 세션의 이미지 참조, SVG 업로드 허용, 카메라 건너뛰기 중복 탭, 500개 넘는 세션 초기화 시 kv 잔존.
- search-celeb: single 모드 다중 선택 잔존, 클라이언트 이동 시 제목 잔존.
- celeb-vibe: 통계 폴백의 의상 색 오류(흰 배경), 흰 배경 클리핑, 얼굴 검출기 실패를 '가림'으로 표시, `[object Event]`·영문 권한 오류 노출, `?warning=` 쿼리가 Notice 제목과 본문에 같은 문구로 두 번 표시, 참고용 톤 목록 표시.
- personal-color-report: 변형 되돌림 시 userSelected 유지, 4단계(전신) 화면 시각 패턴 불일치·진단 준비 카드의 전신 썸네일 없음.
- 분류기: 색상각 경계·저채도 처리는 고쳤지만 원형·축 보정·웜 % 기울기는 여전히 경험값이다(§8의 3번).
- 데이터: 공유 DB에는 데모 세션(얼굴 2, 전신 3), 이번 단계에서 다시 만든 리포트 2개·가이드 4개, 연예인 분석 3개(그중 데모 사진 측정 1개)가 있다. 스모크는 자기가 만든 기록만 지운다. 마무리 검증은 격리 데이터 폴더에서 했고 공유 DB는 바꾸지 않았다.

마무리 검증(2026-11-24) 이후에도 남은 것:

- 스모크(`scripts/smoke.mjs`)는 완료된 얼굴 분석이 하나도 없는 빈 DB에서 `GET :3101 /api/face/latest` 404를 실패로 센다(57/58). API 동작은 맞고, 스크립트 수정은 이번 수정 범위(pocs/, README, 이 문서) 밖이라 그대로 두었다. 공유 DB처럼 데모 세션이 있으면 58/58이다.
- 좌표 범위 검증(−0.5~1.5)은 camera-body 저장 경로와 camera-face 분석 요청에만 넣었다. core 공용 스키마(`Point2Schema`, `Landmark3Schema`)는 저장된 옛 기록을 읽을 때도 쓰여 그대로 두었다. 본 개발에서는 입력 계약과 저장 계약을 나눠 입력 쪽에 범위를 두는 것을 권장한다.
- 강행 분석 이전에 만든 가이드는 `limitations` 필드가 없다. 원본 연예인 분석이 남아 있으면 화면에서 다시 판단해 경고를 띄우지만, 분석이 삭제됐으면 경고가 없다. 다시 만들면 필드가 채워진다.
- 생성 직후 경고는 같은 탭의 sessionStorage로만 넘어간다. 새 탭으로 열거나 저장소가 막혀 있으면 가이드의 기본 안내(Mock이면 'AI 서술을 사용할 수 없어…')만 보인다.
